## Forma esperada del cambio

- Un resultado enfocado por pull request.
- Incluye pruebas cuando cambie el comportamiento.
- Actualiza la documentación pública cuando cambie el comportamiento público.
- Evita reformateos o refactors no relacionados.

## Checklist del pull request

- [ ] El alcance está claro.
- [ ] Las verificaciones relevantes pasan en local.
- [ ] No se incluyeron secretos, URLs privadas, datos personales ni detalles de infraestructura.
- [ ] La documentación es correcta.
- [ ] La solicitud de revisión incluye contexto, evidencia de validación y limitaciones conocidas.

## Reportar problemas de seguridad

No abras issues públicas que contengan vulnerabilidades, credenciales o detalles
sensibles del sistema. Usa el contacto privado de seguridad del repositorio o el
canal de reporte mantido por la organización.
