# Contributing

## Expected change shape

- One focused outcome per pull request.
- Include tests when behavior changes.
- Update public documentation when public behavior changes.
- Avoid unrelated formatting or refactoring.

## Pull request checklist

- [ ] Scope is clear.
- [ ] Relevant checks pass locally.
- [ ] No secrets, private URLs, personal data or infrastructure details are included.
- [ ] Documentation is accurate.
- [ ] Review request contains context, validation evidence and known limitations.

## Security reporting

Do not open public issues containing vulnerabilities, credentials or sensitive system details. Use the repository's private security contact or organization-maintained reporting channel.
