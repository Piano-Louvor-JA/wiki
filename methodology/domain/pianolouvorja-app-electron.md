## Regras de ouro
1. **Botões precisam PARECER botões** (borda/fundo/hover) — texto plano não passa no review do o PO.
2. **Paridade web↔app é LITERAL** de <clone local do projeto>/app.
3. Testes com vídeo: **música sacra IASD** (Athus, Vox, Arautos do Rei), nunca mundana.
4. **Setting global + override por item da liturgia, com cascata na execução**: preferências de player externo (`playerId`) e motor PPTX (`presentationEngine`) seguem `override explícito do item → global das Configurações → fallback interno`. 'default'/'auto' no modal = SEM override (não persiste no item — senão salvamento polui). TODOS os fluxos de execução que tocam mídia precisam da cascata (o usuário usa o botão que você não instrumentou).
5. PR review do Ezequias antes de merge. **Fluxo Git OBRIGATÓRIO (docs/DEPLOY.md, vale pros 3 repos app/web/apk): `feat/*|fix/*` → PR com base `staging` (NUNCA main) → merge → `chore/version-X.Y.Z` → PR staging → PR staging→main → build local release → GitHub Release na tag.** No apk a Release da tag publica notes+APK e dispara auto-update (UpdateService consulta releases/latest). Ao abrir PR: sempre `--base staging`; auditado em 12/09 — PRs #53/#54/#55 do apk estavam pra main e foram retargeteadas via `gh api repos/:org/:repo/pulls/N -X PATCH -f base=staging` (o `gh pr edit --base` falha com erro de Projects classic).
6. **Antes de implementar UI nova, checar se já existe MAS está oculta**: seções de Configurações usam `constants/sections.ts` (flag `hidden: true`) + `routes.ts` (redirect de rota existente). A aba Mídia inteira (YouTube, PPTX engine, Player externo) ficou meses invisível assim — usuário "não tem" o menu, mas o código está completo. Procurar `hidden: true`, `redirect:` e cards órfãos em `src/modules/settings/components/` antes de criar qualquer card novo.
7. **Eletron dev roda o build de `dist/`** — feature nova só aparece depois de `npm run build` + restart do Electron; o usuário sempre confere na tela, não no log. Verificação final tem que ser visual/CDP no app vivo, não só build verde.
8. **Naming de UI é pro usuário LEIGO, não pro dev**: o PO leu "LouvorJA Classo (Delphi)" como erro de grafia grotesco. Renomeado pra "Migração do LouvorJA antigo (Classo)" — nomeia cards/labels pela FUNÇÃO percebida pelo usuário; termos internos (Classo, Delphi, engine) vão na descrição, nunca no título. Se ele questionar um nome, considerar as hipóteses dele antes de afirmar (ele pode estar certo sobre a INTENÇÃO mesmo errado sobre o fato — "não quiz dizer clássico?").
9. **Não duplicar cards entre abas de Configurações** (YouTube estava em Geral E Mídia) — ao reativar uma aba oculta, auditar imports duplicados nas views.
10. **Verificar se a feature existe DE VERDADE no código antes de implementar/assumir**: memória de sessão antiga ("LocalCustomStore, ids negativos, sem auth") era decisão de design que NUNCA virou PR — o editor ainda bloqueava criação sem login. `grep` no staging antes de citar funcionalidade como existente (14/09: o bloqueio foi descoberto em produção, não no plano).

## Pitfalls (mordidas reais desta base)
- **write_file pode vazar linha de warning do bash no topo do arquivo** (`/usr/bin/bash: warning: setlocale...`) → `SyntaxError: Invalid regular expression flags` no boot do main process. Sempre `head -1` em .mjs recém-criado antes de rodar o app.
- **`npm install <novo-pacote>` pode podar dependências transitivas** que o código usava (fflate sumiu ao instalar @cliqz/adblocker-electron) → declare dependências usadas como explícitas.
- **vue-tsc --build usa cache incremental** — erro fantasma de assinatura antiga; usar `--force` para confiar no resultado.
- **`onBeforeSendHeaders` aceita UM listener por session** — youtube-embed.mjs já registra; adblocker plugs no mesmo gancho (compatível, mas ordem importa). **E o `disable()` do adblocker faz `webRequest.on*Request(null)`, que limpa listeners de OUTROS módulos** — sempre re-registrar o fix de Referer após enable E disable do blocker (ver `references/adblocker-and-crossplatform-regressions.md`).
- **Comentário no código pode mentir sobre escopo**: "só filtra YouTube" estava no adblocker.mjs mas a lib filtrava `<all_urls>` + injetava cosmetic/CSP. Ao investigar regressão, auditar o código real da dependência em node_modules (comportamento de `enableBlockingInSession`), não o comentário do nosso wrapper.
- **IndexedDB de youtube.com no userData corrompido** (checksum mismatch) — Electron recupera sozinho, mas gera ruído no log de boot; não é bug.
- **Conflitos de merge**: `setWindowOpenHandler` no main.mjs e GeneralView.vue são pontos quentes (YouTube vs MediaFolder/Backup cards) — manter AMBOS os lados.
- **DevTools NÃO abrem no electron:dev por padrão** — o script não seta `ELECTRON_OPEN_DEVTOOLS=1`. Sem isso o Electron roda como "app" e o usuário não consegue inspecionar. Subir com `ELECTRON_OPEN_DEVTOOLS=1 npm run electron:dev`. Alternativa agnóstica de env: CDP na :9222 (main.mjs registra `remote-debugging-port`) + websocket com `suppress_origin=True` (handshake 403 sem isso).
- **SFC Vue: componente colocado depois de `</template>` é ignorado pelo compilador SEM erro** — estado reativo funciona, handler dispara, mas o componente nunca monta e o botão "não faz nada" (caso AppConfirm no editor, 13/09). Verificação: setupState true + seletor do componente ausente no DOM. Ao mover blocos com patch, conferir se caíram DENTRO do `<template>`. Detalhe e receita CDP em `references/password-reset-email-and-editor-debug.md`.
- **`.env.local` divergente da API em teste**: app dev apontando pra produção enquanto a feature nova só existe na API local = 404 silencioso e UI sem feedback. Trocar `VITE_PALCO_API_URL` e REINICIAR o dev server (env não é pega por HMR). E migrations: verificar schema dos DOIS bancos (local + produção) antes de testar CRUD — `ALTER TABLE` aplicado só num deles reproduce 500 já corrigido no outro (e WAL não checkpointado esconde a coluna de conexões readonly).
